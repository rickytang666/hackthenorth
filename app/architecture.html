How it works

1. CaptureThe browser reads the microphone or a clip with the Web Audio API and sends 20 ms PCM frames over a WebSocket. Frames are paced against the wall clock, so what you hear and what you read stay in step.
2. RecoverCohere Transcribe, adapted with LoRA, runs on a Baseten H100 behind a WebSocket endpoint and returns a revised transcript roughly every 400 ms. Only the shared prefix with the previous hypothesis is treated as settled; the rest is shown greyed because later audio can still change it.
3. ScoreNeither candidate model ships a usable confidence signal, so we compute one from token log-probabilities. Above 0.879 the transcript is accepted. Below it the system asks, offering beam-search alternatives with the model's own best guess first.
4. SpeakThe confirmed sentence goes to the voice renderer: MeloTTS generates the speech, then OpenVoice V2 repaints it with a voice print taken from the speaker's own recordings. Audio arrives about a second after the sentence ends.

Offline adaptation

The bottom band of the diagram is training, which happens once rather than per request. TORGO dysarthric speech was used to adapt two candidate recognizers, Cohere Transcribe and NVIDIA NeMo Parakeet. Both were scored with one evaluator and one text normalizer, and Cohere won on the only matched comparison, so it is the model the live path calls.

Two decisions worth knowing

Only the encoder is adapted. Dysarthria is an acoustic problem, not a linguistic one, and the encoder holds 91.8% of this model's parameters. The adapter trains 3.4M weights, 0.166% of the model, in 10.6 minutes.

Voice conversion, not voice cloning. OpenVoice transfers timbre only and leaves articulation to MeloTTS. Cloning the full delivery from a dysarthric reference would reproduce the slurring, which is the thing the system exists to remove.
